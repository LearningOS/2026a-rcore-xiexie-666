# 实验四报告：文件系统与硬链接（ch6）

## 一、功能实现总结（200 字以内）

给 `DiskInode` 增加 `nlink` 字段（创建时置 1），并实现三个系统调用。`sys_linkat`(37)：在目标目录里追加一条目录项指向源 inode，源 inode 的 `nlink` 加一；同名或目标已存在返回 -1。`sys_unlinkat`(35)：把命中的目录项整槽清零（不缩小目录，保证后续仍能追加），`nlink` 减一；归零时才释放全部数据块（直接块 + 一级/二级间接块）并回收 inode 位图，最后同步缓存。`sys_fstat`(80)：`File` 特性新增 `stat` 默认实现，`OSInode` 填入 `dev/ino/mode/nlink`，按 fd 逐段拷回用户态。此外把上一章的 stride 调度、`sys_spawn`、`sys_mmap/munmap` 与带页表校验的 `sys_get_time` 一并迁移过来，保证前向兼容。

## 二、问答作业（ch6）

### 1. root inode 起着什么作用？

root inode 是 easy-fs 文件树的根目录，也是**所有路径解析的唯一起点**。`EasyFileSystem::create` 建好超级块后，把 inode 编号 0 分配给它，超级块里的 `root_inode_id` 记下这个编号；`root_inode()` 就是用这个编号构造出的 `Arc<Inode>`。它和普通文件 inode 结构完全相同，只是类型标记为 DIR，其数据块里存的是根目录的目录项数组（每项 32 字节，记录名字和 inode 编号）。

内核侧所有操作都从这里出发：`open`/`create` 取路径的第一段，在 root inode 的目录项里查名字，找到后得到下一级 inode，再继续；`link`/`unlink` 也只在 root 目录里增删目录项。INITPROC 就是通过 `open("ch6b_initproc")` 从这里被找到的。

### 2. 如果 root inode 中的内容损坏了，会发生什么？

分几种情况：

- **`size` 被破坏成 0**：根目录被认为是空的，任何绝对路径的第一个分量都查不到，`open`/`create` 全部失败，`link`/`unlink` 全部返回 -1；内核启动时找不到 INITPROC，直接 panic。整个文件系统实际不可用。
- **`size` 被改得远大于实际、或数据块编号被改坏**：目录项数组会读到垃圾内容，解析出非法 inode 编号，可能读到无关文件的 inode、把数据当目录项解释，甚至访问到数据区之外，触发 `expect` 失败而 panic。
- **`nlink`/`type` 被破坏**：类型若不再是 DIR，`create`/`find` 会按普通文件处理而报错；`nlink` 被减到 0 时，unlink 的判定会错误地提前回收根 inode 与它的数据块，文件系统直接失去根目录。
- **间接块指针被改坏**：目录项数量超过 28 个后要经一级间接块访问，指针错了就会读到别的块，目录内容错乱。

共同点是：root inode 是唯一的入口，它坏了并没有"上一层"可以回退来恢复，所以除了整盘重新 mkfs 之外没有自愈手段。这也说明了为什么真实文件系统都要给超级块和根目录做冗余与校验（日志/备份超级块）。

### 3. ch7 的问答题（按要求并入本报告）

**(1) 举出使用 pipe 的一个实际应用的例子。**

最典型的是 shell 的管道命令，例如 `ls -l | grep rcore | wc -l`：shell 为每个 `|` 建一个 pipe，`fork` 后让 `ls` 的 stdout 指向管道写端、`grep` 的 stdin 指向读端，`grep` 的输出再接下一个管道，三个进程并发流水执行，中间结果不必落盘。类似的还有 `cat big.log | gzip > big.log.gz`（边读边压缩，内存占用是常数）、`git log | less`（分页查看），以及编译器把汇编输出直接管道给汇编器。

**(2) `__sync_synchronize()` 这行代码的作用；去掉它可能导致什么错误，为什么？**

它是**全屏障（full memory barrier）**：既阻止编译器在它前后搬动内存访问（编译器屏障），也向硬件发出 fence 指令，阻止 CPU 的乱序执行、store buffer 和 cache 层次把屏障两侧的访存重排，从而保证"它之前的写对其它 hart 可见"这件事在"它之后的读"之前完成。

在这段伪代码里，`A` 和 `B` 是两段虚地址映射到**同一段物理内存**，所以写 `*A` 之后再读 `*B` 其实是同一个物理字的读回。去掉这一行会有两类错误：

- **编译器层面**：`A` 和 `B` 的指针类型和地址都不同，编译器不认为它们别名，可以把 `*B` 的读提前到 `*A` 的写之前（甚至把 `*B` 的读结果当作常量折叠），于是读到旧值，`*B != 0xabab` 判为 ERROR。
- **硬件层面**：写操作先进 store buffer，读操作可能越过它先被执行；若这段共享内存还被其它 hart 观察（多核场景），别的 hart 也可能先看到读、后看到写，出现"写丢失"的现象。

因此这里需要一个显式的 happens-before 关系：屏障之前的写必须在屏障之后的读之前完成。注意它只提供顺序保证，不提供原子性，真正需要原子性的地方还得配合原子指令或锁。

## 四、对本次实验的看法（可选）

- 本章真正写下的代码行数不算多，但**读 easy-fs 的存储布局**花的时间最多：超级块 → inode 位图 → 数据位图 → inode 区 → 数据区，以及直接块、一级间接块、二级间接块和 32 字节目录项这几层换算，每一处都要把"第几个块/第几个 inode"算清楚，改 `DiskInode` 结构体大小时还要连带重算 `inode_area_blocks`。
- `unlink` 的难点在"彻底删除"：必须沿直接块、一级间接块、二级间接块逐级归还数据块，并且只在 `nlink` 归零时才做，同时释放 inode 位图位；只删目录项不回收虽然也能过测例，但那不是硬链接语义。我把删除做成"目录项整槽清零但不缩小目录"，这样后续追加目录项不会覆盖到别人。
- 一个记录在案的性能发现：模板里 `Inode::write_at` 每次写完都调用 `block_cache_sync_all()`，而一次 `write` 往往只弄脏几个数据块，于是 16 个缓存帧里的 inode 块、位图块被反复回写。`ch6_file3` 要写 1.4MB，重复回写让它在本地 30 秒的评测超时里跑不完（功能全对、只是超时）。我改成写回：脏块留在缓存里，由帧淘汰和 `create`/`clear`/`link`/`unlink` 处的显式同步负责落盘，同时把块缓存从 16 帧调到 128 帧。同一个测例的耗时从"跑不完"降到有余量的水平。这是第一次遇到"实现正确但被超时判失败"的评测，值得记一笔。
